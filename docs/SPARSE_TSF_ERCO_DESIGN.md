## 1. 目的和不可改变的边界

在已经固定的 ERCO 168→24 小时协议上，运行论文作者的 SparseTSF，建立与 persistence、seasonal24 可比较的验证基线。不预设一定优于朴素方法，不将本次任务适配称为原论文完整复现或研究创新。

用户已明确：不自行构建神经网络。直接实例化作者 `models.SparseTSF.Model`，不重写 `forward()`，不增加融合层、注意力、预测头或物理约束。保留作者已有 linear / mlp 分支，本次首先运行 linear；不自动启动 MLP 或超参数搜索。

现状依据：用户回传的服务器日志显示数据准备和两个朴素验证基线均 PASS，窗口为 train=5635、val=1441、test=1447，X=(168,11)、y=(24,10)。这是用户提供的服务器运行证据，不是本助手远程执行结果。

## 2. 原模型来源与适配方式

- 作者仓库：[lss-1138/SparseTSF](https://github.com/lss-1138/SparseTSF)。
- 固定提交：`b8c2740eecc84d8095ffce49ba5acafe68e53bb8`，沿用本项目 `reproductions/01_SparseTSF_TPAMI2026/source-lock.json`。
- [模型文件](https://github.com/lss-1138/SparseTSF/blob/b8c2740eecc84d8095ffce49ba5acafe68e53bb8/models/SparseTSF.py)：Conv1d 聚合、周期重排、作者 linear/MLP 映射、均值恢复。
- 该固定源码与期刊发表时使用的精确代码版本是否完全相同，尚未建立证据；不能把固定当前源码等同于确认发表时版本。

候选方式：直接使用作者完整训练入口，需要另行适配默认数据划分和每轮测试行为；另写外层训练适配，可以直接复用现有数据协议且不动模型。推荐后一种。自行改写网络不在本次选项内。

适配时传入模型的配置：seq_len=168、pred_len=24、enc_in=11、period_len=24、d_model=128、model_type=linear。d_model 仅在作者 mlp 分支起作用。长度必须能被周期整除。

数据流：

```text
历史输入 [B,168,11]
    → 作者原 Model / forward
    → 原始模型输出 [B,24,11]
    → 按字段名称在模型外选择目标列
    → 预测 [B,24,10]，与真实目标计算损失
```

选取的目标为九类净发电量和综合发电侧 CO₂ 因子。负荷不参与目标损失与指标。不仅检查列数量，还核对字段顺序和输入/目标标准化参数的一致性，避免取错列或反标准化错误。

**模型能力说明：**原版各通道独立计算、共享参数。当前负荷通道既不能影响其他通道输出，也不参与损失，因此不会为该基线提供跨变量预测信息。不同目标会共同更新共享参数，但这不等于模型利用跨能源输入关系。保持 11 列接口是为了兼容既定数据协议，不宣称负荷在这个基线中起作用。

训练前检查实际导入路径及模型和所需 `layers/Embed.py` 来源内容，记录源码哈希；不能仅凭目录名称宣称使用了原模型。源码检查失败时停止，不自动覆盖或修改用户的作者源码目录。

## 3. 固定数据与评价协议

继续读取服务器已生成的 `data/processed/erco_168_24_v1/manifest.json`；核对观测文件哈希，复用已保存的字段、起点和仅用训练段拟合的标准化参数，不重新划分或拟合。

- 训练目标结束边界：2023-09-01 00:00 UTC，不含该时刻。
- 验证目标结束边界：2023-11-01 00:00 UTC，不含该时刻。
- 输入过去 168 小时，预测未来 24 小时，每小时一个起点；完整目标窗口不得跨集合。
- 此阶段只构建训练和验证 DataLoader，不对测试起点执行模型推理、不输出测试指标。
- 读取准备清单和观测表会访问完整文件；不把“未计算测试指标”说成“从未读取测试文件内容”。

训练损失为十个目标在训练段标准化尺度上的等权 MSE，平均覆盖 batch、24 个预测步及 10 个变量。这样不直接混合 MWh 与 kg CO₂/MWh 的原单位误差；它也不是只优化碳因子，必须如实记录。

最佳 checkpoint 按完整验证集的同口径标准化 MSE 最小选择。最终加载该 checkpoint，在原单位下分别输出每个目标及每个预测步的 MSE、MAE、RMSE。碳因子的 MAE、RMSE是重点报告项，但不得事后更换 checkpoint 选择规则来挑选更漂亮的结果。

与两种朴素方法比较时必须一致：同一观测哈希、同一验证起点、同一目标、同一原单位指标。不得直接与 ETTh1/Electricity 上的误差数字比较，不对不同单位的原始误差求总平均。不使用含大量零值能源的 MAPE 作为主指标。单种子和重叠窗口不足以证明统计显著性。

## 4. 第一轮训练参数（已确认）

参数参考作者 [Electricity linear 运行脚本](https://github.com/lss-1138/SparseTSF/blob/b8c2740eecc84d8095ffce49ba5acafe68e53bb8/scripts/SparseTSF/linear/electricity.sh)、`exp/exp_main.py`、`run_longExp.py` 和 `utils/tools.py`。本次是迁移到新任务的起始配置，不声称是作者为 ERCO 选定或已经最优的配置。

| 项目 | 配置 |
|---|---|
| 模型 | 作者 SparseTSF linear 分支 |
| 随机种子 | 2023，记录 Python/NumPy/PyTorch 随机状态设置 |
| 优化器 | Adam，初始学习率 0.02，weight_decay=0 |
| batch size | 128 |
| 最多 epoch | 30 |
| early stopping | 验证标准化 MSE 连续 5 轮未严格降低即停止 |
| 学习率 | 沿用作者 type3：第 e 轮结束后，e<3 时保持初始值，否则设为 0.02×0.8^(e−3)，供下一轮使用 |
| 训练精度 | float32，不启用 AMP；记录 TF32/确定性设置，不承诺跨硬件逐位相同 |
| DataLoader | 仅训练起点打乱；num_workers=0；各集合均保留尾批次 |
| 设备 | 正式运行要求服务器 CUDA 可用，失败时不悄悄退回 CPU |

外围训练流程与作者完整脚本的差异必须记录：本项目 UTC 划分、固定 scaler、11→10 外部目标选择、保留尾批次、epoch 损失按实际元素数加权，以及不逐轮评估测试集。严格“未降低”包含相等情况；作者 EarlyStopping 对相等值的处理可能不同。本次保持网络不变，不声称完整训练流程逐行相同。

出现非有限输入、输出、损失或梯度时失败并记录原因。已有运行目录不得覆盖；失败后由用户决定是否修改参数、创建新运行，不自动重试。

checkpoint 从第一次有效验证起保存，后续验证严格改善时更新本次运行的最佳权重；不是每一轮都产生一个新 checkpoint 文件。训练结束加载最佳轮权重而不是直接使用最后一轮。此阶段不实现中断续训，不将“保存最佳模型”等同于可精确恢复优化器状态。

代码和操作说明可同步到现有 GitHub 仓库；原始数据、处理表、checkpoint、预测和日志继续留在被忽略的运行目录，不扩大数据公开范围。保留现有未提交实验记录，不动旧脚本和作者网络文件。

4. 验证通过后只提交本次文件并推送现有公共仓库，给出服务器 `git pull`、源码预检和一次 linear 训练的准确命令。
